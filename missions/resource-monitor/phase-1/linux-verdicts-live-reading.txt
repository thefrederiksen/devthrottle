Resource Monitor - phase 1 - the verdict functions - live reading on devlinux (Linux), 2026-10-15

WHAT THIS IS, AND WHAT IT IS NOT.
This task is pure functions (ResourcePressure, SlownessDiagnoser, ProcessTreeUsage,
SessionProcessMembership). It has no probe, so it cannot print a ResourceSample the machine took by
itself; that is the Linux probe's proof. Instead, the operating system's own figures were read BY
HAND at one moment (below, with the commands), typed into ResourceSample values held constant over
60 seconds (13 samples, 5 seconds apart), and handed to both verdict functions through a throwaway
test that was deleted after the run and is not committed. The process list was not read by hand, so
it is given as unreadable and no culprit process is named - which also exercises that path.

The machine was under heavy disk load from this session's own Release build of the solution.

How the figures became a sample:
  processor busy  = 100 - %idle - %iowait from mpstat = 100 - 37.85 - 40.95 = 21.2 (waiting on the
                    disk is idle processor time, as the Linux probe counts it)
  memory          = MemTotal and MemAvailable from /proc/meminfo
  swap used       = SwapTotal - SwapFree
  disks           = iostat %util as busy, r_await and w_await as milliseconds per read and write,
                    lsblk ROTA as the kind (1 = Spinning, 0 = SolidState)
  root volume     = df, on sda, sdb and sdc (lsblk -s); /boot/efi is sdc1
  stall           = /proc/pressure "some avg10"; run queue = the 1-minute load average

DOES IT AGREE WITH THE MACHINE?
----------------------------------------------------------------------------------------------------
- Diagnosis: Disk, the spinning hard drive sdc. The machine's own figures say programs waited on the
  disk 69% of the time against 0.15% for the processor and 0.37% for memory, sdc 78% busy at 67 ms
  per write and 141 ms per read, the two solid-state drives under 1% busy. Same cause as the
  mission's 2026-10-15 morning readings. Agrees.
- Processor Normal at 21% busy, though the load average is 46 on 32 cores: the load counts the
  programs waiting on the disk. Agrees with mpstat.
- Memory Normal, 15.0 GB available of 39.1 GB. Agrees with /proc/meminfo.
- Disk activity Normal: sdc at 78% is under the 80% amber limit, and the Linux disk stall (69%) is
  lower than that. The meter's limits are the mission's; the diagnosis is what names this trouble.
- Swap Critical: 6.1 GB of 8.0 GB used is 76%, over the 75% red limit. Agrees with /proc/meminfo.
- Disk free Normal after the fix: / is 91% free, /boot/efi 99% free. Agrees with df.
