DevThrottle Architecture

The authoritative, rebuilt-from-scratch architecture documentation for DevThrottle: cc-director, the Gateway, the Cockpit, and the mobile client.

This is a clean-room rebuild. A document is authoritative only once it has been deliberately re-vetted and placed in this docs/new_architecture/ area. All documents here are HTML.

What is left in the legacy docs/architecture/ tree, stated precisely, because "not trusted" was too blunt to act on and the code disagreed with it. On 14 September 2026 that tree went from 171 files to 66: 105 finished work artifacts were deleted - mission briefs addressed to session ids, phase manager briefs, dated review verdicts, handovers and QA reports, several still saying "active mission" about work that ended in July. None was referenced by any code, skill or workflow.

What remains is not disposable and is not yet re-vetted. It is the topic architecture for six areas this tree does not cover - Gateway, Cockpit, Wingman, mobile, dictation and security - plus their diagrams, and eleven documents that live SOURCE CODE cites by name. Those six areas are the next consolidation, not a deletion: until each is re-authored and verified here, the legacy document is the only architecture they have.

Conventions

  • HTML only. Every architecture document in this area is delivered as HTML.
  • One idea, one document. A rule is stated once, in the document that owns it, and linked to from anywhere else that needs it. Never restated - two written sources for one rule drift, and the drift is invisible until somebody acts on the stale one.
  • Say what is NOT built. A document that describes a design without saying whether it shipped is worse than no document: it reads as current in the same voice as the true paragraphs around it. Every document here names its unbuilt parts explicitly.
  • Reference code by symbol name (class, method, field), never by line number, because line numbers drift on every refactor.
  • A claim gets checked, not carried. When content moves between documents, each claim is re-verified against the code rather than copied on the strength of having been written down before.
  • No dates in filenames. A dated filename makes a document look disposable, which is how each of the retired predecessors came to be ignored rather than updated.
