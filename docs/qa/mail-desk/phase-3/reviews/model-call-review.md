# Review of pull request 4230: the Mail Desk model call

Reviewed commit `e2013cdc5` on branch `mail-desk-p3-model-call`, against section 5 of `docs/qa/mail-desk/phase-3/CONTRACT.md` on branch `mail-desk-phase-3`. The reviewer read; it built nothing and fixed nothing. The seat that built the work decides what happens to each finding.

## Findings

### 1. One failure path is not a typed failure: an unexpected exception from the web client escapes the question

**What breaks.** `MailDeskModel.AskAsync` (`src/CcDirector.Gateway/MailDesk/MailDeskModel.cs`, lines 306 to 320) catches only `OperationCanceledException` and `HttpRequestException`. Any other exception the web client raises leaves the method as an exception, not as a `MailDeskModelResult` with `Kind = Failed`. The contract (section 5, "Result") says every question ends in a label, off-labels or a failure, and the brief for this review asked that every failure path end in a typed failure, never an exception escaping into a screening run.

**Proof.** A reply with a success status whose `Content-Type` header names a character set the runtime does not know (`application/json; charset=no-such-charset`) passes the status check on line 277, and then `ReadAsStringAsync` on line 281 throws `System.InvalidOperationException`: "The character set provided in ContentType is invalid. Cannot read content as string using an invalid character set." I ran this through a throwaway test over the existing fake handler (not committed, removed afterwards, tree checked clean). The exception escaped `AskPersonOrSpamAsync`; no result came back, and no "AskAsync FAILED" line was logged, so the question's timing and error kind are lost too.

**Why it must change.** The class is, by the contract, shaped like `HostedCandidateJudge`, and that class (`src/CcDirector.Gateway/Transcription/HostedCandidateJudge.cs`, lines 158 to 163) ends with a catch of `Exception` that logs only the exception's type name and returns "no ruling". `MailDeskModel` dropped that last catch. With it gone, a proxy or load balancer in front of the model that answers a success status with an odd `Content-Type` turns one email's question into an exception in whatever loop task F writes around it. Whether that loop survives it is task F's business; this class's promise is that it never has to. The fix is the judge's: a final catch that records the exception's type name (never its message, which could carry the host or the body) as a typed failure with its own error kind, and logs the usual "AskAsync FAILED" line. This is the external-service boundary, which is where the coding standard puts a catch; it is not a fallback that hides a problem, because the error kind names it on the decision row.

**Test gap.** No test sends a reply the web client cannot read as a string, so nothing would have gone red for this. A test with the character-set reply above would.

## Notes that are not findings

These proved no harm against the contract. They are recorded so the Tech Lead sees them once.

- **Phase 0 parsed answers more leniently than the contract does.** Phase 0's `parse_answer` (`docs/qa/mail-desk/phase-0/c-model/model_sample.py`, lines 110 to 116) strips the reply, strips a trailing full stop, and upper-cases it before matching, so `a` and `A.` counted as the label. Section 5 of the contract says the reply's text, trimmed, must be exactly one listed letter, and this pull request does exactly that (`a`, `A.` and `AB` are off-labels, and a test holds each). So the code meets the contract, but phase 0's measured label rate was taken with the lenient parser, and the production off-labels rate can be higher than phase 0 measured if the model ever answers a lower-case letter or a letter with a full stop. That is the contract's choice, not a defect here.
- **The entitlement gate.** The pull request's own description asks whether an entitlement scope applies and says it added none. I confirmed only the fact it rests on: the three comparable included-model factories in `GatewayHost.cs` (about lines 2549, 3766 and 3851) each call `AiGate.EnsureAllowedForTenant` before reading the key, and `MailDeskModelFactory.Create` does not. Section 5 of the contract does not mention the gate, so this is not a finding against the contract; it is the Tech Lead's decision, as the author says.
- **Cost of a call that failed.** A timeout, a non-success status or an unreachable backend returns `CostUsd = null`, although the backend may have billed the call (a timeout after generation, for instance). The contract accepts this ("a question not asked by then is a failure"), so the spend limit is held on replies with a token count only. Noted so task F does not read `null` as free.

## What was checked and found correct

- **No answer outside the listed letters can become a label.** `IndexOfLetter` (lines 332 to 338) matches the trimmed reply ordinally against exactly the letters generated for `labels.Count`, and the label is `labels[index]`. The route labels (`RouteLabels`) and the route lines in the prompt (`BuildRoutePrompt`) are built from the same `RouteChoicesWithUnsure` sequence, so letter and label cannot drift. Tests cover `C` on a two-label question, `a`, `A.`, `AB`, the empty reply and a sentence, each as off-labels.
- **Confidence is never invented.** It is set only on a label answer, only when the reply carries a first token, and only when that token's trimmed text equals the answered letter (lines 296 to 298); otherwise null. Tests cover log probabilities present, absent, and present for a different token than the one answered. There is no path that writes 1.0.
- **A reply with no token count is a failure.** `ParseReply` returns null for either count when `usage` is missing, when the property is missing, when it is not a number, when it is not a 32-bit integer, or when it is negative; `AskAsync` then fails with `no-usage` before any cost is computed (lines 286 to 288). Tests cover no `usage` object, no prompt count and no completion count.
- **Nothing of the email, and never the credential, reaches a log line.** The two log lines on the happy path carry the question name, the label count, the answered letter or "off-labels", the confidence, the token counts and the elapsed time; the failure line carries the question name, the error kind and the elapsed time. The reply text is never logged. The unreachable error sentence carries the exception's type name only. The factory logs the key's name, never the key, and the tag's `ToString` prints "key-owner" or "tenant", never the tenant identifier or the service token. The log test writes eleven questions across five reply shapes plus a thrown connection error into a sink and searches it for every distinctive field and the key, with at least 22 lines required so an empty sink cannot pass.
- **The deadline.** A `CancellationTokenSource` on the injected clock bounds both the send and the body read (lines 249 to 250, 275, 281). A deadline cancellation is `timeout`; the caller's token is `cancelled`, including when the caller cancels first. The test advances a virtual clock to one millisecond short of 15 seconds and checks the question is still waiting, then past it. I changed the deadline to 16 seconds and the test went red (after 1 minute 40 seconds; I did not look into the delay).
- **The request.** One test asserts the property list is exactly `model, messages, temperature, max_tokens, logprobs, top_logprobs, stream` with no others, the values 0, 2, true, 5, false, the model `devthrottle/wingman-fast`, the two messages, the Bearer header and the feature header. The factory tests assert the account and service token headers for a hosted tenant and their absence for the local tenant.
- **The cost arithmetic.** `(input * 0.36m + output * 0.40m) / 1_000_000m` in decimal, exact; 250,000 input and 500,000 output tokens give 0.29 dollars, and one million of each gives 0.36 and 0.40. The pair lives in `IncludedModelPrice` beside `IncludedModelId` as the contract asks.
- **The prompts.** The three embedded files are byte-for-byte phase 0's (`cmp` on each pair), and a test holds that. The system prompt is trimmed as phase 0's script trimmed it. The preview is cut at 200 characters, never through a surrogate pair, and the fill is a single pass so a subject reading `{preview}` is shown as written.
- **No key, no hosted endpoint.** `ResolveWingman` never throws (it returns the one hosted endpoint for every mode), so the only "no endpoint" case is "no key", and the factory returns a model that fails every question with the contract's sentence and makes no call. A hosted tenant without the service credential fails every question with the message that names the setting.
- **No retry.** One request per question; the non-success test asserts a single recorded request.
