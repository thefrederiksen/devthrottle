## Findings

### F1. A timed start of the same check is not refused, so the switch has a shape that bypasses it

**What:** the refusal lives in `TriggerService.ReportCheckAsync` and reads `MailDeskStart.Is(trigger)`, a predicate
over a `TriggerEntity`. A definition may also put a check on a timed start (a schedule with a check, Factory
Definition phase 5b). That report goes to `DueCheckService.Report` through the same route, and `DueCheckService`
consults no Mail Desk switch: it reads the count, begins the start, and starts the seat through the cron starter.

**The harm:** with Mail Desk OFF, a published `mail-desk` factory whose definition names `checks/screen.py` on a cron
start records its run and starts the `mail-desk` seat on every count above zero. That is exactly the "count above
zero starts the seat" fallback the contract's row 2 says the predicate exists to prevent, and section 5.10 of the
mission (which the contract says wins where they differ) says "a Mail Desk start's report is refused" without
limiting it to interval starts. The pull request and the README disclose this gap honestly; disclosure does not close
it, because nothing in the Gateway stops a definition from being published in that shape.

**Why it must change (one of two ways, the Tech Lead's call):** either `DueCheckService.Report` applies the same
refusal, on the job's factory and check path, before `BeginDueStart` (the predicate can take the two strings rather
than a `TriggerEntity`, so both callers share it); or the contract records that a Mail Desk start is an interval
start only AND the definition check refuses a `mail-desk` definition whose schedule names `checks/screen.py`, so the
bypassing shape cannot be published. As it stands, phase 2's template is the only thing holding the switch, and a
template is not a gate.

### F2. The "only the administrator route writes the switch" test cannot fail for the writer it guards against

**What:** `MailDeskSwitchKey_IsWrittenOnlyByTheSwitch_NeverByTheAccountsSettingsRoutes` makes two text scans. The
first (who names the key) is sound: any write through `TenantSettingsStore` must name the key. The second asserts that
the only file containing the literal `mailDeskSwitch.Set(` is the administrator endpoint. That matches a lower-case
local variable name, ordinally. `GatewayHost` holds the switch as the property `MailDeskSwitch`; a call
`MailDeskSwitch.Set(tenant, true, ...)` added there, or `_mailDesk.Set(...)` anywhere, names neither the key nor that
spelling and passes both assertions.

**The harm:** the test's name and comment promise that an account cannot be switched on by anything but the
administrator route. A second writer through the class passes it, so the promise is not what is proven. The first
assertion still proves the narrower fact (no settings route writes the key), which is the fact the comment argues from.

**What must change:** either narrow the test's name and comment to what the first scan proves and drop the second,
or make the second scan find callers of the method rather than one spelling of one variable, for example by scanning
for `.Set(` in every file whose text names the type `MailDeskSwitch` and asserting the exact list. A guard that
cannot fail for the thing it names is the pattern `checks-that-fail-open` describes.

### F3. The proof transcript does not reproduce as written

**What:** four commands in `docs/qa/mail-desk/phase-1/switch/README.md` (lines 44, 48, 59 and 68) and in the pull
request body pass a multi-word `-Reason` without quotes, for example `-Reason phase 1 local proof: on`. Run as
written on this machine the script fails before its body runs:

```
mail-desk-switch.ps1: A positional parameter cannot be found that accepts argument '1'.
(exit 1)
```

The output shown under those lines came from a quoted invocation (the last transcript line is quoted and matches).

**The harm:** the README is the committed proof for phase 6, whose Developer will run these lines. Run as written
they fail, and the failure reads as a defect in the script. **Fix:** quote the four reasons in the README and the
pull request body. No code change.

## Checked and found sound (for the record)

- **Correctness against the contract, rows 1 to 4:** key `mail_desk_switch` in `All`; `MailDeskSwitch` with no
  machine switch; `MailDeskGate.Group` answering 404 with no body for an account that is off and for no bound
  account; `GET`/`POST /gateway/admin/mail-desk` behind the same service-token denial as the factory agents route,
  exempt from the device-key gate; `MailDeskStart.Factory`/`CheckPath` as named; the refusal 409
  `{"error":"mail_desk_off","detail":...}` inside the report handling. All as written.
- **Refusals record nothing:** the refusal sits after the one read of the trigger and before the per-trigger
  semaphore, `RecordCheck`, `KeepState`, `BeginStart` and the claim renewal. The test asserts no run row, no state
  row, no start, empty claim, no last-check facts and no lock held, and it fails when the refusal is removed
  (verified above). The administrator route refuses before `Set` on every missing field, an unknown account, and a
  missing token; each refusal test reads the decision back as null.
- **Tenant isolation:** the switch is read and written under the `TenantId` bound to the request (the gate) or to
  the Director's route (the refusal); the administrator route accepts only an identifier `TenantRegistry.ListAll`
  holds, so a mistyped identifier records nothing. `IsOn_OneAccountSwitchedOn_IsOnForThatAccountOnly` and
  `AdminSet_KnownAccount_SwitchesThatAccountOnlyAndReadsBack` prove one account's decision does not leak to another.
  Factory agents ON with Mail Desk OFF answers 404 on every Mail Desk route, the case the owner's grant depends on.
- **A stored decision that cannot be read throws** rather than answering off (`"null"` is tested). An unreadable row
  surfaces as a 503 on the administrator route and a 500 on a gated route or the report, which is the stated intent.
- **The check path cannot be spelled around the predicate:** `DefinitionPaths` refuses a backslash and requires
  `checks/<name>.py`, so `checks/screen.py` has one spelling in a published definition; the ordinal comparison is
  right. `checks/Screen.py` is a different file, tested as not a match.
- **Every `TriggerService` construction in the repository** is in `Gateway.UnitTests` and passes `mailDeskOn`; nothing
  outside that project constructs it, so nothing else fails to compile.
- **The script:** exactly one of `-On`/`-Off` (exit 2), `-Reason` and `-Account` mandatory, the token only through
  `cc-secrets run` into `ADMIN_SERVICE_TOKEN` and never printed, `-DryRun` sends nothing, read-back compared to what
  was asked, exit codes as documented. It runs under PowerShell 7 here; the 5.1 claim rests on `HttpClient` and
  `Add-Type`, which is plausible but not run.
- **Public-repository rule and attribution rule:** both hold (searched, above).

## Observations, not findings

- With Mail Desk OFF and factory agents ON, `GET /directors/{directorId}/triggers` still hands the screen check to the
  Director every interval. The Director runs it, reports, and is answered 409 each time; the check's state is never
  kept, so it re-reads the same mail next time. The contract chose the report as the refusal point, so this is inside
  the contract, but the Tech Lead should know that phase 2's check runs against the mailbox whatever the switch says,
  and that the Director's log carries one 409 per interval while the account is off.
- The 409 body is `{error, detail}` while the other refusals on the same route are `{code, error}`. The contract names
  this shape and the pull request discloses it; the Director logs both the same way.
- The gate tests prove the gate on a route the test itself maps; `GatewayHost` maps nothing into the group yet, by
  design. The routes pull request must add each real route to `ExpectedMailDeskRoutes`, as the comment says.

Three findings: F1 is the one that bears on whether the switch holds; F2 and F3 are small and cost nothing to fix.
