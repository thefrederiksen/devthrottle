Fleet Manager Improvement - the design

Final, 20 September 2026. You said go. The design is settled and the building has been handed to a Delivery Lead, a session that answers to you. From the Architect of the Fleet Manager Improvement mission. Read against the main branch as of today.
Settled - nothing needed from you

Summary

All four things you asked for can be built, and none needs new machinery - each one extends a piece that already exists. I recommend four phases, smallest first, each merged on its own.

  1. Raise a session to your permissions. You choose a session and the Gateway treats its key as acting for you: it may message any session with no limits, type into sessions, press menu keys and answer stops - everything you can do to your fleet from your own screens. The Fleet Manager is raised when you set it up. Every other session keeps every limit. Each thing a raised session does is recorded as that session acting for you.
  2. A Fleet Manager screen on the phone. Today the phone has none - only the pinned first row, which opens the ordinary session chat. The Cockpit page moves into the shared code both apps use, so the phone shows the same conversation, the same cards, the same waiting list and the same walkthrough.
  3. Talk to it on the phone. Dictation and spoken narration are already shared pieces that work against any session. The phone screen mounts them against the Fleet Manager. The one new piece: a card has no spoken version today, so the Gateway writes one.
  4. One front door. The Gateway marks the Fleet Manager's session as "talk to it through the Fleet Manager screen". The Cockpit, the phone and the Director all show that session read-only with a link to the screen, and you keep a deliberate unlock for the day it is stuck.

What you saw, now on record: you talked to the Fleet Manager's session directly in the Director, and the Cockpit's Fleet Manager page did not reflect it. So phase 4 is a fix and not tidying: that session stays visible in the Director but takes no input, and everything goes through the Fleet Manager screen. It needs a new Director release, so it lands last. I did not reproduce the page falling behind and found no cause in the code; the first task of phase 4 is to reproduce it, so the cause is known and not guessed.

Phase 1 - raise a session to your permissions

What happened on 19 September. You asked the Fleet Manager to tell a session on the Mac mini "merge 3151". Four minutes later you gave a follow-up for the same session and the Gateway refused it: one message per recipient every ten minutes. Your own words, passed on by the Fleet Manager, were stopped by a rule meant for sessions chattering at each other.

How the Gateway tells you from a session today. Your phone and Cockpit carry a device key. Every session carries a session key. One Gateway rule (SessionKeyGuard) lists what a session key may call, and refuses the rest - in particular typing into a session, interrupting it, pressing its menu keys, and answering a stop, which are yours alone since 16 September. A second rule (FleetMessagePolicy) holds the message limits.

The change. The Gateway keeps a list of raised sessions for your account. When a request arrives with a raised session's key, both rules treat it as you:

Ordinary sessionRaised session
MessagesSix an hour, one per session every ten minutes, only to sessions it started or that started itNo limit, to any session on your account
Typing into a session, interrupting it, pressing menu keys, answering a stopRefusedAllowed
The Fleet Manager page, walkthrough and placementRefusedAllowed
Devices, sign-in, billingRefusedRefused for now (decided above)
Anything outside your account, or that only the developer of DevThrottle can do, such as shutting down the GatewayRefusedRefused, always
Raising another sessionRefusedRefused

Raising and lowering. From your own device only: "Raise to my permissions" in a session's menu, in the Cockpit and on the phone, with one plain sentence saying what it means, and "Lower it" in the same place. Setting up the Fleet Manager raises it as part of that same action, and the grant follows the mark through a restart or a move. A raised session shows a mark on its row everywhere, so you can always see which ones act for you.

The record. Everything a raised session does with the raised power is written down as "this session, acting for you": what it did, to which session, when. One place to read it, so "who typed that into my session?" always has an answer.

A side effect worth having. Today, when a session the Fleet Manager owns stops on a menu, the Fleet Manager has to bring it to you because only you can press keys. Raised, it can press the key the Wingman read - for questions with no risk. Anything irreversible, anything that spends money, anything that grants a standing permission still comes to you; that is its conduct, and it does not change.

What this reverses, said plainly. The 16 September ruling that no session ever types into another. It stays true for every ordinary session; a raised session is the exception you make by hand. The Fleet Manager's conduct still tells it to queue by default and to type into a working session only when your words call for it - the power is yours delegated, and so is the restraint.

Also in this phase: the Fleet Manager's conduct and skill tell it today that it is held to six an hour and cannot press keys. Those words change with the rule, in the one shipped source.

Proof. Tests on both rules: a raised session sends twenty messages in a minute to a session it does not own and all queue; it types into a session and presses a menu key; an ordinary session is refused each of those with today's sentences; a session that says it is raised but is not on the list is refused; a raised session is refused device enrollment, refused raising another, refused anything in another account and refused shutting down the Gateway; lowering takes effect on the next request; every raised action appears in the record.

Phase 2 - the Fleet Manager screen on the phone

Today. The phone pins the Fleet Manager as the first row of the session list with its sessions folded under it. Tapping it opens the ordinary session chat. There is no Fleet Manager screen. The phone's route file says so in words: "the Fleet Manager is on the Cockpit only" - a ruling from the first Fleet Manager mission, which this mission reverses.

What exists to build on. Everything the Cockpit page shows is already decided on the Gateway: every card, heading, button and the exact words a button sends. The code that fetches it is already in the shared package. Only the page itself - the layout - sits inside the Cockpit.

The change. Follow the rule Settings already follows: one page on two surfaces. The conversation, the cards, the waiting list and the walkthrough move into the shared package. The Cockpit keeps its frame (wide, panel on the right). The phone gets its own frame: the conversation full height, the composer at the bottom, "Waiting on you" as a count in the top bar that opens the list, "Take me through them" one item per screen.

Phase 3 - talk to it on the phone

What exists. The dictation dialog, the recorder, the status strip and the narration player are shared pieces, and each works against a session by its id. The phone's session voice screen is a thin view over them.

The change. The phone's Fleet Manager composer gets the same microphone button a session has. Your words reach the Fleet Manager unchanged, under the same transcription rules as everywhere - no new path, so no new place for a word to be altered. When it answers, the Wingman reads the stop as it does for any session that answers to you, and the spoken version plays.

The one new piece. A card has no spoken version today. When the Fleet Manager files a Ready, a Finding or a Decision, the Gateway writes one spoken line for it alongside the rest of the card - what it is, and the choices - so the phone can read a card aloud and you can answer by voice. The phone never composes that sentence itself.

Answering a card by voice. What you say goes to the Fleet Manager as your words, with the card's prefix the Gateway already supplies so it knows which card you mean. Pressing the button stays available. Nothing irreversible is ever triggered by a voice match alone: merge and close keep their buttons.

Proof. The isolated Gateway rig with the fake microphone: dictate to the Fleet Manager, see the words arrive unchanged, hear narration for its answer and for a card. Failure cases: microphone refused, transcription down, narration not ready.

Phase 4 - one front door

Today. Nothing anywhere treats the Fleet Manager's session differently for typing. The Director, the Cockpit's session view and the phone's chat, terminal and voice all accept your input to it like any session.

The change. The Gateway decides, once, that the marked Fleet Manager's session is "reached through the Fleet Manager screen", and puts that on the session every client already reads - the sentence to show and the link to offer. No client works it out for itself.

  • Cockpit and phone: the session's chat, terminal and voice views show it read-only, with the Gateway's sentence and a button to the Fleet Manager screen.
  • Director: the terminal for that session shows the same sentence and does not take keystrokes. The Director learns which session it is from the Gateway's push, the same way it learns a session's color.
  • Gateway: the typing routes refuse direct input to that session from anything but the Fleet Manager screen and the Gateway's own event delivery, so a client that has not updated yet cannot slip past.
  • The unlock: from your own device only, for that one session, until it next goes idle or you lock it again. Each use is recorded.

Why last. It needs a Gateway deploy and a Director release, and it must not land before the phone screen exists - otherwise the phone would lock you out of the only way you have to reach the Fleet Manager from the couch.

Proof. Tests on the Gateway ruling and the refused routes. A QA report: typing blocked in the Director, the Cockpit and the phone; the screen still works; unlock works and is recorded; a restarted Fleet Manager carries the lock to the new session and releases the old one.
