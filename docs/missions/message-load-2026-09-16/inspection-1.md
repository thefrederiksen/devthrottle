# Slice 1 inspection

**Verdict: FAIL for merge.** Two session-key paths defeat the intended input or relationship boundary. The passing tests below establish the implemented cases; they do not establish that these two paths are closed.

## Findings, ranked

### High: a session key can still type a verdict answer into another session

`src/CcDirector.Gateway/Util/SessionKeyGuard.cs:283-288` explicitly allows `POST /sessions/{sid}/turn-verdict/answer` for a session key. `src/CcDirector.Gateway/Api/GatewayEndpoints.cs:3062` maps it; `:5641-5646` refuses a session key only while verdict colours are off, and `:5652-5672` constructs a prompt channel and asks it to send the answer when colours are on. This contradicts brief rulings 2 and 17. The handoff flags the path and records the Architect's decision to close it, but the code has not done so.

**Prove it:** With verdict colours enabled, a live unanswered verdict, and a session key, POST its valid option to this route. Observe the Director's prompt command. A guard unit test asserting refusal for that method and path should fail on this tree. The live verdict prerequisites limit this side door; they do not make it an owner-only path.

### High: a session-key spawn can invent a supervisor relationship used by the message gate

`src/CcDirector.Gateway/Api/GatewayEndpoints.cs:3881-3919` accepts an agent's `NewSessionRequest` and sends it to the Director after `SpawnOrigin.TryEstablish`. `src/CcDirector.Gateway/Api/SpawnOrigin.cs:89-92,120-137` pins `ParentSessionId` to the credential but accepts any GUID-shaped `ControllerSessionId` supplied in the body. The new roster row's controller is then used by `PartyFrom` at `GatewayEndpoints.cs:3168-3175`; `FleetMessagePolicy.cs:153-158` treats that controller as permission to message the named supervisor. The sender of a message is credential-derived (`GatewayEndpoints.cs:3237-3254`), and neither message body nor header directly supplies a controller. The weakness is upstream: a session key can choose the controller of a newly spawned session independently of the credential's parent identity.

**Prove it:** Spawn a session with a session key and set `controllerSessionId` to an unrelated live session's GUID. In the new session, send to that claimed supervisor; the policy will see a permitted relationship. The unrelated session will also see the new row as its worker for broadcasts (`GatewayEndpoints.cs:3313-3332`), though it did not start it. Confirm the Director's create path retains the supplied controller; this review traced the Gateway request and policy, not a live spawn. This is a relationship bypass if that create path retains it.

### Medium: reading can acknowledge a message before its text reaches the recipient

`src/CcDirector.Gateway/Messaging/FleetMessageStore.cs:166-184` stamps `ReadAtUtc` and commits before `FleetMessageService.cs:121-131` builds the response. A process crash, serialization failure, or failed HTTP response after the commit means the ordinary next inbox read omits the message. `--all` retrieves only the latest 20 previously read rows (`FleetMessageStore.cs:57-58,169-175`); later reads can displace it, and retention ultimately purges it. Brief ruling 9 calls read the acknowledgement, so this is an acknowledged delivery risk inherent in the chosen protocol, rather than a code contradiction.

**Prove it:** Commit the store read, abort before the HTTP body is received, then retry `GET /fleet/inbox`. The message is absent from `unread`; `all=true` can recover it only while it remains among the 20 recent reads. The existing once-only test proves normal completion, not this failure interval.

### Low: the text cap and policy advice are not pinned to the approved values

`FleetMessageLimits.cs:36` sets `MaxTextLength` to 16,000, but `FleetMessagePolicyTests.cs:283-290` builds both boundary lengths from that same property. Changing the default cap to another positive value leaves those tests green. The six other numeric/time defaults are pinned to literals at `FleetMessagePolicyTests.cs:51-62`. The policy's `PutItInYourReport` and `LeaveItInYourSession` constants (`FleetMessagePolicy.cs:119-125`) are likewise asserted by reference to themselves at `FleetMessagePolicyTests.cs:79-83,148-150,238-240`; changing their wording while retaining nonempty, distinct strings can leave these tests green. The latter are wording contracts, not numeric limits.

**Prove it:** Change only the default cap to 8,000 and run the touched suites; the boundary test follows it. Change either advice sentence to another distinct sentence and run the policy tests. This review did not mutate product code.

### Low: the broadcast CLI's no-queue exit condition differs from its own claim

`tools/cc-devthrottle/src/session_ops.py:1244-1246` says a broadcast with nothing queued exits 1, but `:1274-1275` exits only when there are neither queued nor duplicate results. An all-duplicate response therefore exits 0 with zero new records. This is consistent with a duplicate single send's exit 0, but the broadcast contract should state which outcome is intended.

**Prove it:** Supply a `fleet/broadcast` response containing only `status: duplicate` rows and inspect the CLI exit code.

## Checks that held

- **Input route census.** The routes that can reach the named tunnel inputs are `POST /sessions/{sid}/prompt` (`GatewayEndpoints.cs:3356`), `/interrupt` (`:3546`), `/escape` (`:3560`), `/fanout` (`:4547`, prompt copies at `:4683-4691`), `/compact-context` with `continuePrompt` (`:4385-4405`), and `/turn-verdict/answer` (`:3062,5652-5672`). The first four are refused to session keys by `SessionKeyGuard.cs:122-149`; compact-continue is refused by its body-aware route at `GatewayEndpoints.cs:4387-4395`. Plain compaction remains reachable. Verdict-answer remains reachable under its stated prerequisites. `POST /sessions/{sid}/message` and `POST /fleet/broadcast` now write rows (`GatewayEndpoints.cs:3219-3256,3269-3333`), rather than issuing prompt commands. This census is of the specified Gateway tunnel commands; it does not prove that no other Director verb can affect a live screen.
- **Tenant and inbox identity.** Every `FleetMessages` query in `FleetMessageStore.cs:100-213` uses a context made with an explicit tenant. `GatewayDbContext.cs:1207,1353-1362` installs its tenant filter, and `GatewayDatabase.cs:500-507` scopes the context. The inbox route takes the calling session from the authenticated credential, not a path, query, body or header id (`GatewayEndpoints.cs:3342-3353`). Read, count, duplicate, rate and purge queries therefore share the filter. These checks assume the authentication middleware binds the correct tenant to the credential; they do not test credential issuance.
- **Rates and duplicates.** The store counts rows newer than `now - SenderWindow` and excludes granted whole-account copies (`FleetMessageStore.cs:138-151`); the policy rejects when the count is already six and when the last recipient send is less than ten minutes old (`FleetMessagePolicy.cs:166-187`). `FleetMessageService.cs:45-51,78-92` uses one UTC clock value for judgment and writing. Persistent rows preserve counts across a Gateway restart. The unread duplicate lookup has no time window (`FleetMessageStore.cs:149-150`), so identical text cannot be resent while the prior copy is unread; that implements brief ruling 3's exact-duplicate drop and its read acknowledgement. The policy and store tests cover the sixth/seventh send, spacing boundary, restart and duplicates; this check does not cover concurrent writes by separate Gateway processes because the lock is process-local (`FleetMessageStore.cs:46-50,98-120`).
- **Schema and retention.** Both SQLite and Postgres `AddFleetMessages` migrations create `fleet_messages` with tenant-leading key and indexes, ring/stuck columns, and reply columns (`src/CcDirector.Gateway/Data/Migrations/20260916195943_AddFleetMessages.cs:12-59`; `src/CcDirector.Gateway.Migrations.Postgres/Migrations/20260916195948_AddFleetMessages.cs:12-59`). The model mapping and snapshots contain the entity (`GatewayDbContext.cs:770-794`). Slice 1's insert writes none of the later ring or reply fields (`FleetMessageStore.cs:105-119`). Purge selects only old rows already read or stuck (`:201-213`), so an ordinary old unread row remains. I did not run the Postgres migration against a database.
- **Command line.** A single queued send prints its ID; duplicate returns success; a refusal or the old `{ "accepted": true }` shape exits 1 (`session_ops.py:1210-1238,1309-1321`). The inbox printer splits every newline, escapes non-ASCII without truncating, and offers `--all` and JSON (`:1331-1385`). `session report` sends `kind: report` (`:783-795`). The self-test checks the response's `status == "queued"` (`:1811-1815`); it does not independently read the record or prove the recipient saw it. Its own description at `:1786-1792` acknowledges that limit.
