Mission report, for the owner

Message Load: messages no longer interrupt

What changed for you, what is proven, what is not, and what went wrong on the way.

Architect session 120. 16 and 17 September 2026. Slice 1 merged as commit a8fa8041 (pull request 2970); the rest as pull request 3016, merged as ddc78ac4. The post-merge fix from the final review is commit 7b6afbdc (pull request 3041). Release v2.6.0 carries it to your Directors.

1. What it does for you

A session can no longer be interrupted by another session. A fleet message is a record in a Gateway inbox. Nothing is typed into a session until it has finished its turn and its composer is empty, and then only one fixed line: "N fleet messages waiting. To read, run: cc-devthrottle message inbox".

Sending is rare and gated. A session may message only the session that started it and the sessions it started. Six an hour, one per recipient per ten minutes, exact duplicates dropped. Everyone else is refused with the reason. message ask, which blocked a session for two minutes, is gone.

No agent can type into another session by any route. Prompt, interrupt, escape, fan-out, compaction follow-up and verdict answers are refused to agents. The inspectors found and closed three side doors that were open before this mission: an agent could still answer a verdict into a session, could name any live session as the owner of a session it spawned, and could raise a hand on someone else's behalf.

Nothing is lost silently. An unread message is rung again after five minutes and marked stuck after three rings, and the sender is told. A message that asks for a reply gets one in the sender's inbox, or a notice when the deadline passes. Every screen shows "2 messages waiting" on the session row.

Your snooze survives a doorbell. Your decision of 17 September: another agent's message never wakes a session you parked. Your own typing still does.

Director restart's restore is now the Director's own act. Your decision of 17 September: because a session may no longer spawn a session owned by someone else, the Director performs the restore spawns itself, owners come only from the capture, a seat starts at most once, and one Director holds a workspace at a time.

2. What is proven, and how

  • Twelve independent inspections (eleven before the merge, one after it) by a reviewer of a different agent family, none trusting the builders' reports. They found real defects at every stage: 2 high in slice 1, 3 high in the doorbell, a critical one in restore. Every finding was ruled on, fixed, and confirmed closed by a later inspection.
  • Every guard watched failing. Each fix was reverted or mutated, the named test seen red with the reported symptom, then restored. The breaks are recorded under docs/missions/message-load-2026-09-16/.
  • Seven live runs with real agent sessions on a test Director on this Mac: a message sent mid-turn was not typed until the turn ended; your unsent text, and even three typed spaces, held the ring; a worker that never read was rung three times and marked stuck, and the sender was told; a doorbell kept an armed snooze and your first keystroke ended it.
  • Postgres. Both migrations and this mission's collation columns proven on real PostgreSQL on the Windows machine.
  • Every suite on the final tree matches the known Mac-only baseline with no new failure; all nine checks on the pull request are green on Windows, macOS and Linux.

3. What is not proven

Only two agents get the doorbell. The composer reader exists for the two agents with captured screens. Other agents' messages wait until read and never go stuck; the row line shows them waiting. The second agent was proven on captured screens, not live, because it ran out of usage credit during capture.

A race of milliseconds remains. Between the Director's last look at the screen and its first keystroke, the agent can start a turn on its own. The worst case is one short fixed line queued behind the current tool call, never lost text. Written into the code as a gap.

A read is marked before the answer is sent. If the connection drops in between, the message is recoverable for 24 hours with message inbox --all, but the reader has to ask.

Not exercised: the hosted Gateway with more than one tenant, the graphical Director and your installed Director, a live Director restart with the new restore.

No baseline count. The messages-per-day figure was never measured; the count exists in the Gateway's activity table, but nobody queried it. The report cannot say "from N a day to M".

4. What went wrong on the way

  • The inspector was the bottleneck. Codex hit its usage limit three times, at two inspections a window, and stalled the merge queue for hours each time. No other agent family is installed on this Mac or the Windows machines.
  • Continuous integration fought us. The .NET check takes an hour and a half; main moved several times an hour; the first pull request conflicted twice while waiting. Your latest-only rule (pull request 2991) fixed the queue; a mistake of mine nearly cancelled a green run by pushing a record file to the branch, caught and moved to a record branch.
  • An account spend limit stopped a Manager mid-merge. Its work was on disk; a fresh Manager finished it under your new login.
  • Seats died at spawn twice: one because a spawn that timed out client-side had in fact landed (two Managers in one worktree, one stopped at once), one because a first prompt never arrived (issue 2841's shape).
  • The review after the merge found the restore-mark binding could still be taken by a Hello. You had chosen to merge first, so it became a follow-up: fixed on main the same night as commit 7b6afbdc, its other findings filed as issues.
  • The release fought back too. v2.5.0 had never actually been tagged; main went red on a help-text test after our merge and on a flaky Gateway test, both fixed forward; the release checks ran four times; the deploy's outage gate failed on a slow slot swap while production served the new code. The release seat ended up on the Windows machine because this Mac's Director kept dropping its Gateway stream (issue 3058).
  • The words slice found hidden files teaching the old behaviour that the inspector's search skipped, in the agent-expert skill folder. A test now walks the whole tree.

6. Decisions that were yours, and what you said

  • All five design questions of 16 September: "all recommended".
  • Snooze versus the doorbell, 17 September: keep the exception.
  • Restore versus the spawn owner pin, 17 September: make restore a Director act.
  • Continuous integration: only the newest commit on a branch gets a run, main included.
