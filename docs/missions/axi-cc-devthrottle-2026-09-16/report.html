Mission report · issue 2922

cc-devthrottle now speaks agent

Every cc-devthrottle command now follows the AXI standard (Kun Chen, axi.md): compact list output, full ids and names, one plain state per session, filters that also narrow --json, and errors an agent can act on. It is proven on macOS, Windows and Linux, and re-measured with the issue 2920 benchmark.

Now true of every command

The ten AXI principles, applied

  • Compact output. A count line, a header, one row per record.
  • Few default fields. Three or four; --fields asks for more and lists the valid names.
  • Nothing cut. Ids, names and paths are always whole.
  • Counts included. Totals, breakdowns by state, of N total when filtered.
  • Definite empty results. count: 0 and a sentence, never blank output.
  • Exit codes. 0 success, 1 error, 2 usage error with the valid values listed.
  • No silent fallback. A missing or malformed Gateway answer is an error, never "nothing found".
  • Live state first. No arguments shows the fleet, not the help screen.
  • Next steps. help[] lines with placeholders, never guessed values.
  • Short help. A one-line summary on every command and group; ASCII-only output.

Beyond the brief

Other improvements along the way

Less waiting on continuous integration merged

At your request (pull request 2986): a pull request now runs only the jobs its files can affect, and the lowest-version check runs on Linux only. A final CI result job fails on any failed, cancelled or wrongly skipped job; it protects nothing until you mark it as a required check.

Tested dependency floor merged

The tool now declares Typer 0.16.1 and Click 8.2.1 as its minimums, and continuous integration installs exactly those, so the lower bound is tested rather than promised.

Honest gaps

What is not finished, and what needs you

How the last reviews ran

Codex, Grok and Copilot all ran out of usage near the end. At your instruction, the final review of pull request 2986 was done by a session of the same agent family that built it, so that one change was not checked by a different family.

Public data in edit history

The repository is public. Live fleet rows (mission names, repository paths) had been pasted into eight pull request descriptions. They are redacted, but the old text stays in GitHub's edit history; purging it needs GitHub support, which is your call.

Moved to issue 2972

Skill and workflow pull can still leave a mixed folder if killed mid-write, and do not refuse Windows name aliases such as SKILL.md.. Both predate this mission.

Reported, not changed

These come from the Gateway and are printed as sent: worktree list counts a worktree twice when two Directors on one machine report it (the output says so); worktree paths use forward slashes while repository paths use backslashes; a disabled schedule shows an empty next-run cell.

Not proven

The benchmark covers one frozen fleet, one agent setting and Windows only; four of its six tasks were not re-run after the follow-up fix. selftest still runs only on Windows. The installed tool on the Mac is still the older release until the next update.
