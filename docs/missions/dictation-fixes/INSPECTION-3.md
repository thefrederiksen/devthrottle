# Dictation Fixes — inspection 3

**Verdict: FAIL. Two findings.** I inspected the commits after `eb22cbbce` against rulings G1–G3, then the whole `origin/main...c588b481a` diff against devthrottle#2925–#2929. The builders' report was not used as proof.

## Findings

1. **High — the clock boundary can erase the beginning of the owner's speech.** `src/CcDirector.Avalonia/Voice/BatchDictationRecorder.cs:93-97,329-338` always adds a 50 ms first-buffer delivery margin to the 50 ms ring-down. Consider an ordinary 50 ms first capture buffer delivered as soon as it fills: at T0 = 50 ms, B0 = 50 ms, and the cue begins then. Playback ends 200 ms later; the ring-down ends at capture position 300 ms. The computed boundary is 50 + 200 + 50 + 50 = **350 ms**, so the first 50 ms of speech beginning after the ring-down is written as zeros in both transcription paths. The extra buffer delivery lag may be anywhere from zero to 50 ms; a fixed 50 ms margin can preserve the cue in the worst case only by deleting speech in the faster case. `BatchDictationRecorderReadyCueTests.cs:74-86` sets the first buffer's delivery at 100 ms for 50 ms of captured audio, thereby assuming the full extra 50 ms lag; all four backlog cases inherit that assumption and stay green. This implements G1 as ruled, but conflicts with #2925's acceptance that samples after the cue are untouched and with the mission's reason to stop losing words.

2. **Medium — a microphone's first measured start time is absent from the open selector.** `src/CcDirector.Avalonia/Voice/SpeakDialog.axaml.cs:431-436,465-476,679-696` reads and decorates the device list once during opening, then records the first-audio measurement to config without updating the selector's `ItemsSource`. If a device has no prior history, its entry keeps showing only its name for the rest of this dialog, including while the user can switch microphones or pause and resume. The #2928 figure appears only after the dialog is closed and opened again. `MicStartTimesTests.cs:126-169` seeds history before opening and checks the later record callback separately; it never checks the selector after a previously unused device first delivers audio.
