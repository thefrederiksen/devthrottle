What you get when it is finished

  • Rules the product enforces, not text an agent can ignore. "Never run this command", "never push to main", "never kill cc-director" become rules that stop the command before it runs and tell the agent why, so it carries on another way.
  • Rules where they belong. One rule for every repository, one for a single machine, one for one repository on one machine. The most specific wins, and the Rules page shows which rule decided and which it overrode.
  • One Rules page, on the desktop and the phone. Every rule - screen, hook, start-up - with its firing record: what it caught, when, and in which session.
  • Agents can set rules up for you. Already true on main: an agent can create, change, promote and delete a rule, and every change is recorded against the session that made it. A changed rule always goes back to dry run.
  • Safe to switch on. Every rule starts in dry run and records what it would have done; you promote it when the record looks right.
  • Start-up checks. A session that starts with a missing licence or API key is caught before it wastes a run.
  • Approval from the phone for the commands you want to decide on yourself.
  • Cheap. The hook adds about 4 to 6 thousandths of a second per shell command on Linux, measured. Windows is still being measured.
