Waiting on you

Test suites: what runs by default, what is parked, and what it costs

Written for the owner. One question in the next section, and the table it rests on is further down.

In short

The default local gate runs eight suites in under two minutes. Three suites are parked and do not run unless you ask for them, and one of those three - the Gateway's own unit tests - is the one most likely to matter, because it holds four thousand two hundred and fifty nine tests of the part of the product every client talks to.

Parking it was the right call at the time: it had grown past the two minute ceiling and was making every agent wait. But a green default run now says nothing at all about the Gateway, and nobody reading the word green would guess that. I would like to change one thing about that, and it needs your call.

What I need from you

Which parked suite should we bring back into the default run first?

Neither answer costs us anything permanent - either suite can be parked again. The recommendation is the Gateway suite because it is the gap that reads as coverage and is not.

The measurements

Every number below was taken on this machine on 2026-09-17, from the local gate's own result files rather than from the console summary. Runs by default means the suite is inside the two minute budget and an ordinary local gate run executes it.

The three parked suites add up to five thousand one hundred and eighty nine tests and seven minutes and fifty three seconds. That is the whole trade: the default run stays under two minutes because those seven minutes and fifty three seconds are not in it.

What a green run actually certifies

This is the part that worries me, and it is why I am asking rather than just doing it.

  • A green default run certifies the eight suites in the table above, and nothing else.
  • It runs no web tests against a real browser and no Python tests at all.
  • It builds Debug. What people download is Release, and the release gate is the only run that matches it.
  • A regression inside a parked suite therefore reaches the main branch with every light showing green, and the person who merged it has not done anything wrong.

The gate does print a coverage gap line naming what it did not run. That line is correct, and it is easy to miss, because it sits under a large green number.

What it would cost to un-park the Gateway suite

Three minutes and twenty four seconds today, which would take the default run from one minute fifty to over five minutes. That is not acceptable as it stands, so un-parking it means making it faster first. Two thirds of its time is in one hundred and forty tests that each stand up a whole Gateway; sharing one across a class would bring the suite to about seventy seconds, which fits.

That is a week of work, not an afternoon, which is the real reason this is a question for you and not a decision I should make on my own.

Evidence, and what is not proven

Proven: every count and every duration in the table was read from the result files the local gate writes, not from its console summary, on one machine on one day.

Not proven: the seventy second estimate for a shared Gateway is an estimate. It comes from timing ten of the one hundred and forty tests with a shared instance by hand and multiplying. Nobody has run the whole suite that way, and the ten were not chosen at random.

Not measured at all: what any of this looks like on the build machine, which is slower than this one and runs other work at the same time.
