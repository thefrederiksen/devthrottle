# DevThrottle v2.8.0

A new tool that tells you where your disk went, and the end of a warning banner that was telling you to
fix something that was not broken.

## See where your disk went, before anything is removed

`cc-cleanup-storage` is new in this release. It walks a disk, writes one small record of what it saw, and
reports it. Two commands, `scan` and `report`, and nothing else.

**It removes nothing.** The code to remove anything does not exist yet, and that is deliberate: the part
that reads is worth having on its own, and shipping it by itself means nothing can be deleted by a tool
that has only ever been tested reading.

It is careful about the things that make a naive disk walk lie to you. It never follows a link or a
junction, and counts every one it declined to follow. It never opens a file, so a file that lives in the
cloud is never pulled back down just to be measured, and those bytes are counted separately from the bytes
actually on the disk. A folder it could not read is never silently passed over - every one is counted and
named.

This is the first phase of a larger piece of work on reclaiming disk space. Later phases will act on what
this one finds.

## The Tools board no longer reports cc-secrets as broken

The Director's home screen showed "NEEDS ATTENTION - DevThrottle tools - 9 pass, 1 fail - failing:
cc-secrets (version check: exit 2)". Nothing was wrong with cc-secrets. It stored secrets, ran commands
with them, and signed in to websites exactly as it always had.

The Tools page asks every tool it lists the same two questions: is the program where it should be, and
does `--version` answer. cc-secrets could answer only as a command, `cc-secrets version`, and had never
been given the `--version` flag that every other tool has. So the board asked, the tool refused an option
it had never heard of, and a healthy machine was told to go and fix nothing. That is worse than a silent
failure: it spends your attention on nothing, and it teaches you to ignore the one banner that is supposed
to mean something.

`cc-secrets --version` now answers and exits cleanly. The `version` command prints the same line from the
same place, so the two can never drift apart and give different answers to the same question.

## One tools folder per machine

A machine is meant to have one installed copy of the cc-* tools, at the machine root, with every Director
on that machine using it. The repair meant to keep it that way had the world the wrong way round: it
treated the machine's own copy as the outdated one, treated a copy inside a single Director's folder as
the right one, left every other Director's copy on the path, and only ever ran when somebody pressed a
button on the Tools page.

It is now the right way round, and it runs at every Director start rather than waiting for a button. The
machine's copy is the one that answers. A copy inside a Director's own folder comes off the path,
including one whose folder has already been deleted and left an entry behind. A Director serving a
throwaway root of its own keeps its own tools, because that separation is what makes a test rig safe to
run.

Nothing on your disk is deleted. A copy that has come off the path is still there; it simply no longer
answers a command.

## Also in this release

- **The governance ledger sees hosted sessions again.** Sessions that reach the Gateway through the tunnel
  were not reaching the ledger at all, so the daily report read "0 agent sessions ran yesterday" for eight
  days. The missing seam is now in place, and the daily report no longer carries yesterday's statistics
  when it has none. This is a change to the Gateway rather than to the Director, so it takes effect for
  hosted users when the hosted Gateway is next deployed, not when you update.

## A note on how this release was tested

The usual release gate was not run for v2.8.0. It cannot start without a database server running on the
machine cutting the release, and the machine this was cut from does not have one. Rather than let the
affected suites report themselves as skipped - which reads exactly like a pass - the gate refuses to run
at all, and the release went out on Soren's explicit decision without it.

What is behind this release instead: every pull request in it passed continuous integration on Windows,
macOS and Linux, and the cc-secrets tool suite was run locally in full. The gate itself, and the wider
question of what a release ought to be tested against, is being looked at as its own piece of work.
