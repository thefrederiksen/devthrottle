## v2.10.0 - September 22, 2026

The command line tools learn to hand their answers to other programs, your list of repositories stops
filling up with worktrees, and the Cockpit gets lighter, faster and easier to read.

### Highlights
- cc-gmail answers in JSON: `search`, `list`, `read`, `draft` and `reply` now take `--json`, and every
  answer carries the Gmail thread id, so a script or an agent can follow a conversation from one message
  to the next. Without `--json` the output is exactly what it was. `reply --json --send` is refused, and
  `draft --json` and `reply --json` are refused on an App Password account, because neither can return the ids.
- A worktree is not a repository: a session started in a worktree now counts as a session in the
  repository it belongs to, and adding a worktree with Browse registers its repository. Existing worktree
  rows fold into their repository's row, so the repository list gets shorter instead of growing with
  every worktree you have ever used. Anything that cannot be positively identified as a worktree is left
  exactly as it was.
- The Cockpit's session view opens on Chat: Chat is now the first tab and the one a session opens on,
  with the Terminal one click away. Your own messages are drawn quietly instead of as the heaviest thing
  on the screen, the row of nine buttons under every conversation became one composer, and one density
  switch sets the spacing for the whole window.

### Also in this release
- Factory agents, behind a switch, off by default: a record of what a factory agent did, triggers that
  run a check on your machine and start a session only when there is work, and Factory Agents pages in
  the Cockpit. Nothing of this appears unless `factoryAgents.enabled` is set to `true` in the Gateway's
  config.json. The new `cc-devthrottle factory` and `cc-devthrottle trigger` commands work only against a
  Gateway with the switch on.
- The Cockpit uses less network: answers are compressed, a poll that has not changed is answered with
  "nothing new", a conversation sends only its new part, and the chat stops polling while its page is
  hidden. Older clients get exactly the answers they got before.
- The Fleet Map shows a session on its own machine when the session that started it runs on another. It
  used to be drawn only under its parent, so the machine it actually ran on looked one session short.
- The daily report names the sessions that stopped on a usage limit, instead of printing their ids.
- The Wingman no longer invents a menu: whether a picker is on the screen is now read from the screen
  itself, so a plain question is no longer offered as a list of options.
- The macOS installer no longer needs Xcode. It used to stop with "Could not read the SHA-256 hash" on a
  Mac without working developer tools.
