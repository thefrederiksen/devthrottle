## v2.23.0 - October 17, 2026

The Director now looks before it types: a prompt is never typed into an open question menu, a full-screen view or onto text already waiting in the agent's composer, and is refused with a plain reason instead. A file link in the Chat can open any file the agent named, and a new factory can be created from the Factories screen.

### Highlights
- Look before typing. Before the Director sends a prompt to Claude Code or Codex, it reads the agent's composer.
  When a question menu or a dialog is open, or the composer is not on the screen, nothing is typed and the send is
  refused with a reason that says to answer or close it first; the next prompt after the menu closes arrives as
  normal. When the composer already holds text you typed, the send is refused and your text is left exactly as it
  was. The Director's own leftover line is cleared before typing, never joined onto your prompt. Each check reads
  the screen several times over about a second, so a frame caught mid-repaint is not taken for a menu or for text.
  Pi, whose composer the Director cannot read, is unchanged.
- Chat file links open any file the agent named. In the Chat on the Cockpit and on the phone, a path the agent
  named in the conversation can be opened even when it is outside the session's working folder, and a named folder
  opens as a listing whose files open in place, on the phone as well as on the Cockpit. A plain Unix path written
  without quotes, such as /home/soren/report.pdf, is a link too on a Linux or macOS Director. A path that is not on
  disk, or that the session may not open, shows the Director's own sentence instead of a bare failure, and a
  download refused for the same reason says why. Path chips show the folder and file name, with the full path on
  hover and on Copy path, and a path that is not on disk is greyed. Secrets are never opened, even when named: key
  folders, browser profiles, credential files, macOS keychains and the Director's own protected stores are refused,
  and the hidden folders under your home folder are guarded by the home folder the system records for you, not
  only by the HOME variable, including for a session whose working folder is your home folder.
- New factory on the Factories screen. Where the factory area is turned on, New factory takes a zip of a definition
  folder and imports it as version 1, a draft, of the factory its definition names, then opens its Definition tab.
  A factory that is not published yet shows as its own row on the list and its other tabs say it starts when the
  factory is published. A refused import says why in the Gateway's words: the id is a live factory, an archived
  one, one with a draft already, or the check's findings by file and line.

### Also in this release
- A run now that starts a seat is recorded truthfully. The caller hanging up no longer cancels the start, and a
  start whose outcome is not known gets its own record, start unknown, never "did not run".
- A factory definition publish now judges the whole pairing of a seat's starts to its existing schedules, not
  pairs of two, so a rotation of three or more is refused as a guess and says which starts to tell apart.
- A session that belongs to no factory can create and publish factories, with your approval, where the factory
  area is turned on: `cc-devthrottle factory definition create <folder-or-zip>` makes a new factory's first draft
  through the same checked import, and publish and restore are open to it. A factory's own session is still
  refused, in words. Every publish now records who did it, and the Definition tab's history says so.
- A license problem is loud until it is fixed. When a license check finds a problem, such as a machine with no
  spare license, one alarm opens: a red banner on every page of the Cockpit and the phone with the Gateway's own
  words, one push that names the machine and the kind of problem, and one email to the owner. An alarm already
  open sends nothing more, and one that is no longer true closes by itself.
- Groundwork for approver registration. A Director whose machine offers its browser profiles can register a
  profile it has proven able to approve a sign-in, while the owner keeps the last word; the Director's own daily
  check that uses it is not in this release.
- Groundwork for API mode. The Director can run Pi through Pi's own protocol instead of a terminal, as an opt-in
  per session, with delivery read from Pi's own acknowledgement, and the Gateway records each prompt's receipt and
  the session's live events. There is no switch for it in the app or the command line yet, so nothing changes for
  a session you start today.

New factory, the run records and the Gateway's side of the chat file links are in the hosted Gateway already; a
session creating and publishing a factory, the phone's folder listing, the license alarm and the approver
registration reach it with its next deploy. The download carries the look-before-typing change, the Director's
side of the chat file links with the wider home guard and the plain Unix paths, the new factory definition command
and the API mode groundwork.
