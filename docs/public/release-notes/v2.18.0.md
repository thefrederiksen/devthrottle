## v2.18.0 - October 10, 2026

A Director on Linux now finds Chrome, Edge, Brave and Opera, schedules can belong to a factory seat and can fire at random times or at the quietest minute inside a window, the Mac installer no longer leaves a refused launcher behind, and prompts are no longer refused because of Claude Code's grey suggestion.

### Highlights
- A Director on Linux finds your browsers. Settings, Browser profiles, Which browser now lists Google Chrome,
  Microsoft Edge, Brave and Opera when they are installed from the vendor's own package, and
  `cc-devthrottle browser create` works on Linux. Before, the list was empty and every create said the browser was
  not installed, even with Chrome and Edge on the machine. Firefox is not listed: browser profiles need a Chromium
  browser.
- Schedules that belong to a factory. `cc-devthrottle schedule create` takes `--factory` and `--seat`, and
  `cc-devthrottle schedule link` attaches an existing schedule to a factory seat. A schedule names both a factory and
  a seat, or neither, and the seat must be registered - otherwise the command refuses with a sentence naming the fix
  and nothing is stored. A schedule linked to a factory or seat the registry does not have will not fire. Where the
  factory area is turned on, the Factories screen lists every enabled schedule that belongs to no factory under
  "Schedules outside any factory".
- Random schedules. A third kind of schedule beside recurring and one-off: about N fires a day at random times inside
  a daily window, kept a minimum gap apart, weighted by default toward the hours a person is usually active. Create
  one with `cc-devthrottle schedule create` and `--random <window> --per-day <N> --min-gap <minutes>`, and see the
  times still to come with `cc-devthrottle schedule plan <id>`. The times are worked out the same way every time, so
  a restart does not change them. The Cockpit shows the schedule in words and today's remaining times. A
  `cc-devthrottle` older than this release does not list random schedules.
- Window schedules. A fourth kind of schedule that names a window instead of a time: `cc-devthrottle schedule create`
  with `--window <from-to>`, and optionally `--days`, `--deadline`, and `--after <schedule> --gap <minutes>`. The
  Gateway picks the minute inside the window when the schedule is saved, choosing the time with the fewest other
  scheduled sessions running. `cc-devthrottle schedule load` prints each machine's next 24 hours of scheduled
  sessions, and a new schedule that lands in an hour that is already full is still saved, with a warning naming
  the quietest hour.
- The Schedule page in the Cockpit. It lists only schedules that will still run, under Active, Paused and Historical
  tabs; your own jobs come first, filed under Personal, with factory schedules behind a switch and grouped by
  factory; each machine has a 24-hour load strip against its capacity; and every schedule shows how its runs ended and
  whether it closes itself. A factory's schedules are edited on that factory's Seats tab.
- The Mac install fixes a refused launcher. Every install on a Mac now rebuilds the launcher's launch agent, and the
  Director repairs a launcher that macOS has refused to start, when its launch agent is still in place. A launcher that still will not start no longer fails
  the install: the Director is installed and opened, the launcher line reads Warning, and the last screen says what
  losing autostart means.
- Prompts are no longer refused because of Claude Code's grey suggestion. Claude Code shows a faint guess at your
  next prompt in its empty input box. The Director read that guess as text you had typed, so a short prompt such as
  "go" could be refused as "not delivered", and an idle session could keep putting off its waiting messages. The
  Director now ignores faint text when it reads the input box.

### Also in this release
- `cc-secrets ui` opens a window listing your secrets and settings, with search, Add, Edit and Delete. A secret stays
  hidden until you click its eye. `cc-secrets ask` lets an agent open the same form for you to fill in, so the secret
  never passes through the agent.
- Installers say what happened. The setup command line, the Windows installer and the Mac install script now report
  when an install starts, finishes or fails, and a finished install tells you where to open DevThrottle and sign in.
- On Linux and macOS the desktop Speak dialog now says that desktop dictation is only available on Windows, instead of
  failing with a raw error.
- The updater's state file is never left empty by an interrupted save, which had made every later update check fail
  on that machine.
- Two noisy false errors are gone: a session started in a folder that is not a git repository, and a repository scan
  replaced by a newer one, no longer report a failure.
- Factories: a factory's CEO is now its boss. The manifest key is `bossSeat`, and a manifest still saying `ceoSeat` is
  refused with a message naming the fix. A boss can read its own Factories screen, and
  `cc-devthrottle factory status` prints it.
- The Cockpit: you sit at the bottom of the left rail, with one Settings page in tabs; the menu has three labelled
  sections; Mentor and Reports are under Work for everyone; a team has a Governance tab; Demo mode blurs private
  text on every device on the account; the Fleet Map's colour panel opens and closes; the Factories list is grouped by
  state, can be sorted, and each factory has a Floor tab; and the Reports page no longer says it cannot reach the
  Gateway when the answer is only slow.
- A prompt that was not delivered now shows one small red "Not delivered" chip instead of two large red blocks. Click
  it to see the reason, the words that were not delivered, and Send anyway, Retry or Dismiss. This is in the Cockpit
  and the mobile app.
- A session that asks to talk to another session now shows that as a badge on the asking session, with Approve and
  Deny in its header, instead of a full-width card. The session says how much talking it needs, and Approve allows
  exactly that. On the command line, `cc-devthrottle message request` takes `--amount`, and
  `cc-devthrottle message link answer` takes `--approve`.
- Teams: you can create a team from the Cockpit's Account page, which now lists your teams and your role in each.
- On a Mac, the launcher repair reports every result to central error reporting - repaired, left alone and why, or
  failed - with your home folder and user name taken out.
- The Fleet Manager entry in the Cockpit's left menu no longer shows a red count.
- The Schedule page's editor lets you pick the factory and seat a schedule runs as, so a schedule can be put on its
  seat without the command line.
- More errors reach central error reporting, with private details taken out before they leave your machine: errors
  in the Cockpit and the mobile app (including a prompt the phone could not send), the Gateway's own errors, and
  installer errors from before you sign in. Your user name and machine name are removed by the sender, and a report
  that cannot be sent waits and goes out on reconnect.
- Every cc-* command line tool now reports a crash or a failed command to central error reporting, with the words
  you typed taken out. A plain mistake in how a command was typed is not reported, and the exit code and the message
  you see are unchanged. cc-secrets reports only the command and the kind of failure, never its message.
- A Fleet Manager you start can always type into and message the sessions you started. Before, it could be refused
  after a restart or a move, with nothing on screen to say why.
- Factories, where the factory area is turned on: the last talk is shown in the talking seat's own clock, and the
  "change - coming" label is gone from the Factories screen.

The Not delivered chip, the talk request badge, creating a team, the Schedule page and its factory and seat picker, the random and window schedule
display, the Cockpit changes, the Factories changes and the Fleet Manager fix are in the hosted Gateway. The download carries the Linux
browser detection, the Director's grey-suggestion fix, the Mac installer and launcher repair, the install reports,
the updater and Speak dialog fixes, `cc-secrets ui` and `ask`, the cc-* tools' error reports, and the `cc-devthrottle` command line changes for
schedules, factories and talk requests.
