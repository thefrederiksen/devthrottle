# DevThrottle v2.7.1

DevThrottle was writing a recording of every session's terminal to your disk, for every session, on every
install, and nothing in the product ever read one. It no longer does.

## The per-session terminal log is off by default

Every session the Director ran got a folder under `session-logs`, and the file that filled it was a
byte-for-byte record of everything the terminal emitted. That is not a record of what the agent said. It is a
record of what the screen **painted** - so every spinner frame, every progress bar, every repaint of a status
line was captured, encoded in a form a third larger than the bytes themselves, and wrapped in a timestamp per
chunk.

A single busy session produced 1.1 gigabytes. One machine had accumulated 35 gigabytes across 3,422 sessions,
and 99.6 percent of that belonged to sessions that no longer existed. There was no setting to turn it off, no
size limit, and no age limit.

Nothing in DevThrottle read any of it. It was raw material for work that was never finished. The terminal
evidence the product actually uses is the short, bounded record the Wingman keeps of each turn, and that is
unaffected.

**So it is now off, and turning it on is a decision you can see you made.** In `config.json`:

```json
"session_logs": { "enabled": true }
```

Setting `CC_DIRECTOR_SESSION_LOGS` to 1 or 0 overrides that in either direction for a single run, without
editing a file.

Switch it on when you are chasing a terminal or escape-sequence defect - the raw file is what
`cc-raw-view-harness` replays to reproduce a screen - and switch it off again when you are done. When it is
off, the Director attaches to nothing and opens no file, so the folder is absent rather than empty.

**Your existing `session-logs` folder is left exactly as it is.** This release changes what is collected from
now on, not what is already on your disk. If you want that space back, the folder is under your DevThrottle
data directory and it is safe to delete whole; nothing reads it.

This is the same problem, and the same fix, as the terminal screen recorder that was turned off by default in
an earlier release. That one was found and this one was missed.
