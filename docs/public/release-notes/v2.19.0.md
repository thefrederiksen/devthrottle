## v2.19.0 - October 13, 2026

Desktop dictation now works on a Linux Director, every schedule can be paused in one tap and the whole scheduler can be paused and resumed exactly as it was, every scheduled run says how it went, and a machine holding several Claude accounts can be switched to a spare when one runs out, as an opt-in setting.

### Highlights
- Desktop dictation on Linux. The Dictate dialog in a Director on Linux now records from your microphone and
  transcribes exactly as it does on Windows. It records through PipeWire when that is installed, where you can pick
  any input, and otherwise through ALSA's default input. A machine with neither is told which package to install.
  On a Mac the dialog says dictation is not available there yet.
- Pause everything. The Schedule page and the Factories screen in the Cockpit have one switch that stops every
  schedule from starting, and a banner shows while it is on, so a paused fleet never looks like a broken one.
  Resuming changes no schedule: each is exactly as active or as paused as it was. Pausing stops new runs from
  starting; it does not stop a session that is already running, and no missed run is recorded for a time that
  passed while everything was paused.
- Pause one schedule where you read it. Each schedule on a factory's Seats tab has a Pause or Resume button beside
  it, and the schedule editor has an Active or Paused control, so editing a paused schedule never resumes it by
  accident. The state is called Paused everywhere, in place of Disabled.
- Every scheduled run says how it went. A scheduled session ends by calling `cc-devthrottle run result ok` or
  `cc-devthrottle run result problem "<why>"`, and a run whose session ended without saying is recorded as
  "did not report". `cc-devthrottle run problems` lists the open problems, and `cc-devthrottle run resolve` clears
  one with a reason that is kept.
- License switching, off by default. A machine that holds more than one Claude account can now be moved to a spare
  when the active one runs out. With `licenseSwitching.enabled` set to true in a Director's config.json, that
  Director reports each account's 5-hour and weekly use, the Gateway checks once a minute and sends a switch when
  one is due, and the new Licenses page in the Cockpit shows the accounts, each machine's active account, the switch
  log and a Switch now button. The setting is off unless you turn it on, and with it off the Licenses page has
  nothing to show.
- Claude account usage and sign-ins from the command line. `cc-devthrottle license usage` prints each held
  account's 5-hour and weekly use and when each resets. `cc-devthrottle license sign-in` adds a spare account by
  signing it in through one of the Director's browser profiles, and `cc-devthrottle license renew` signs in again
  every account whose sign-in ends within five days.

### Also in this release
- A session with a voice clip ready is no longer marked "retrying" on the phone. Before, a failed read after the
  clip was made could take the play button off the row and drop the session out of the voice queue.
- Factories, where the factory area is turned on: every seat on the Seats tab says whether it closes itself, from
  how its recent scheduled runs ended, and a factory with a seat that does not is flagged on the list, its card and
  its page.
- Factories, where the factory area is turned on: a factory's page lists its open problems, each with Handle the
  issue, which opens a talk with the factory's boss, and Resolve, which asks for a one-line reason. The Seats tab
  is grouped by shift, and the Schedule page shows each schedule's shift and warns when a run is due close to the
  end of one.
- The Factory Manager, where the factory area is turned on: one standing session can be set over all of an
  account's factories with `cc-devthrottle factory manager set`, and the Factories screen shows it on a card with a
  talk button. A problem in a factory that has no boss goes to the Factory Manager.
- The factory email, off by default: the Gateway can send a report at 08:00 and checks at 16:00 and midnight about
  your factories' scheduled runs, and keeps each one as it was sent. Turn it on with
  `cc-devthrottle factory email on`; `cc-devthrottle factory email list` and `show` read the kept ones, and a
  factory's page lists the emails that covered it.
- `cc-devthrottle license refresh` renews a spare account's key when it has under an hour left.
- The Accounts dialog is gone from the Director's Developer menu. `cc-devthrottle license` holds and switches
  accounts now. The old accounts file is left where it is and is no longer read.
- The release process: the test run before a release is much shorter, the largest suite going from about two hours
  to about nine minutes, and a test that depends on the machine it runs on - a sleep, the real clock, a real
  process - is refused before it can decide a release.

The scheduler pause, the run results, the Licenses page and the once-a-minute license check, the factory email, the
factory page's open problems, the Factory Manager, the shifts, the seat markers and the voice clip fix are in the hosted Gateway. The
download carries desktop dictation on Linux, the Director's license reporting and switching, the
`cc-devthrottle run`, `cc-devthrottle license`, `cc-devthrottle factory email` and
`cc-devthrottle factory manager` commands, and the removal of the
Accounts dialog.
