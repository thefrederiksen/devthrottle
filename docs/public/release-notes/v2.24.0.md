## v2.24.0 - October 18, 2026

License switching now keeps every machine ready to move before an account runs out, says loudly and in one place when something stops it, and lets you tidy up machines that are gone. The launcher brings a crashed Director back by itself, a busy Director can install an update through Smart Restart, and named Director instances are safer and quicker to set up. Pi sessions can now run in API mode, as an opt-in choice when you start them.

### Highlights
- License switching keeps machines ready, and moves them when it counts. These changes apply only where license
  switching is turned on (`licenseSwitching.enabled` in a Director's config.json, off by default). Every minute the
  Gateway works out, for each machine, which account it would move to next and whether it is ready to, and the
  Licenses page shows that on the machine's line. A machine that is not ready is signed in to that account
  automatically through the same Add a spare and Renew now steps you would use by hand, and the Licenses log marks the
  sign-in as automatic. A failed automatic sign-in is tried again after 2, 5, 15 and 30 minutes, then hourly. When an
  account is nearly full, every ready machine moves at once to the best account it is ready for, and one machine that
  is not ready no longer holds the others back. The active sign-in is also renewed when no Claude Code session is
  using it, so it does not quietly expire on an idle machine.
- One license alarm, loud until it is fixed. A license problem now opens an alarm that shows as a red banner on every
  page of the Cockpit, sends one push and one email to the owner, and closes by itself once the problem is gone. On
  the phone the alarm arrives as the push, with no banner, so the app stays usable. It is raised when an account in
  use is at 80% or more and a machine on it is not ready to move, when an account in use is at 80% or more and no
  other account has room (one alarm for the account, saying which account has room again first and when), when a
  machine's reports are refused, when a machine has sent nothing for more than ten minutes, and when an account's
  approver cannot approve. Each alarm names the one thing to do. The push names only the machine and the kind of
  problem, never an account address. An alarm that comes back within six hours of closing is shown again but sends
  no second email or push, and its banner line says how many times in a row it has come back.
- Standing approvers you can see and trust. The Licenses page has a usable approver form: pick lists, the browser
  profiles read from that machine's own Director, and a Save that says what is missing. Each approver row shows who
  set it, its health, why a sign-in cannot reach it and the one thing to do. The Director that approves checks each of
  its approvers once at start and once a day by opening a real approval page and pressing nothing, and an approver you
  have just set is checked within ten minutes while that Director is running. The new
  `cc-devthrottle license check-approver` command runs the same check by hand. Each approval relayed for a renewal is written to the Licenses log. A machine can also offer its own
  browser profiles as approvers with the setting `licenseSwitching.offerApprovers`, which is off by default; with it
  off, nothing new is registered and only the approvers already set are checked.
- Forget this machine. A machine that has been renamed or taken out of service can be removed from the Licenses page
  by the owner. It is offered only for a machine whose reports are refused or that has stopped reporting, and never
  while a sign-in on it is under way. Forgetting it closes its alarms, ends any switch it can never answer, removes its
  approvers and keeps its earlier log rows. A forgotten machine that reports again comes back.
- The launcher restarts a Director that crashed. The installed launcher now watches its Director and starts it again
  when it ends without a clean shutdown, so a crash no longer leaves a machine down until someone notices. A deliberate
  quit, an update and Smart Restart are left alone. After five restarts in ten minutes it stops trying and says so.
- A busy Director can install its update. An update waiting for a Director that always has sessions running now
  offers Smart Restart: every session hands over, the Director restarts and installs the update as it starts. The plain
  install is still never offered while sessions run, and the Cockpit says the same.
- API mode for Pi. New Session has a Connection choice, Terminal or API mode, on the Cockpit, the phone and the
  desktop Director, offered only for an agent that supports it, which is Pi today. Terminal stays the default, and
  `cc-devthrottle session spawn --connection api` does the same from the command line. In API mode the Director runs
  Pi through Pi's own protocol instead of a terminal: the Chat shows the conversation live, each prompt carries a
  receipt that says whether it was queued (with its place in line), delivered or refused and why, and a session
  interrupted by a crash continues in API mode. Take the wheel opens the real terminal on the same conversation, and
  Hand back returns it to API mode, with prompts sent in the meantime written in order. A Director older than v2.23.0
  is refused an API-mode session rather than quietly starting a terminal. Sessions you start in Terminal are
  unchanged.

### Also in this release
- Named Director instances: Create named director instance can copy settings from an existing instance, such as the
  Gateway address, agent settings, folders, repositories, agent templates and dictation corrections. The Gateway key
  is never copied, so the new instance signs in once. Two Directors can no longer run on the same data folder, from
  any program file, and an `--instance` name that is not registered refuses to start instead of quietly running as
  the default.
- A failed launcher self-update no longer leaves the machine without a launcher.
- Codex sessions no longer stop on Codex's update offer, or on trusting a folder that is already trusted for Claude
  Code. A session started by another session, or a factory seat, is refused before it starts when Claude Code would
  stop on its one-time Bypass Permissions warning or on its "Teach auto mode about your environment?" question, and
  the refusal names what to do. The Director never answers either for you. Sessions you open yourself are unchanged.
- Voice: switching voice on for a waiting session now narrates the stop in front of it, and a brand-new voice session
  says there is nothing to narrate instead of counting up to "Voice did not arrive".
- Chat links: plain Linux and macOS paths such as /home/name/report.pdf are now clickable, in the terminal and in the
  Chat alike.
- The phone's file viewer opens a named folder as a listing whose files open in place, as the Cockpit does.
- Session file access guards the real home folder even when HOME is redirected, applies when a session works in the
  home folder itself, and refuses the macOS keychain folders.
- Where the factory area is turned on, the Factories screen leads with the factories, published first and drafts
  after, each with its seat count, next start and last run. The Factory Manager moves to its own tab.
- Factory pages open on a drawing of what the factory does: a lane per seat, from how it starts through the steps its
  definition lists to how it ends, with the newest run painted on it. A factory definition may now list its steps.
- `cc-devthrottle session review` starts a reviewer session and, when a seat cannot work (a usage or spend limit, a
  refused model, a signed-out agent), moves on to the next one by itself, saying which seat is reviewing and why.
- On macOS and Linux, a Director started on a test data root no longer rewrites the tool links in your own
  ~/.local/bin, so deleting that root no longer breaks the command line tools for every session.
- Linux: the Tools box shows tools as available whatever PATH the Director was started with, and `cc-devthrottle
  setup repair` removes a broken launcher unit that restarted for ever.
- Groundwork for Mail Desk, which screens a mailbox for you. It is off for every account and is turned on for one
  account at a time by an administrator, so nothing changes for you in this release.

The Gateway's side of the license changes, API mode, the voice fixes, the Factories screen and its drawings, the
Chat's link detection and the phone's folder listing are in the hosted Gateway. The download carries the Director's
side of license switching and API mode, the launcher's crash restart and self-update fix, Smart Restart for a held
update, the named instance changes, the start-up question refusals, the reviewer command, the terminal's link
detection, the file access guards and the macOS and Linux tool fixes.
