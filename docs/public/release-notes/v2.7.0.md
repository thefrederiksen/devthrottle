# DevThrottle v2.7.0

Several sessions can now work on one repository at the same time, each in its own ready-made copy, and a copy
is only cleared for reuse once its work has provably landed on the remote.

The screen you answer a session from was rebuilt around what you actually do on it, and a report you are sent
now has a page of its own instead of a corner of somebody else's.

## Pooled worktrees: a ready-made copy per session, cleared only when the work has landed

Two sessions in one checkout fight over the same files. The usual answer - a fresh copy per session - throws
away the build output every time and slowly fills the disk with copies nobody remembers.

DevThrottle now keeps a small pool of copies per repository. A session takes a free one, works in it, and gives
it back when it closes. A returned copy is reset and handed to the next session, so the build output in it
stays warm.

**A copy is reset only when its work is proven to have landed.** Not assumed, not "the branch looks merged" -
proven, in order: the copy is the one it claims to be, nothing is uncommitted or untracked, nothing of its own
is sitting in a stash, and every commit in it is either already on the freshly fetched default branch or is the
same change as something that is. When git cannot prove it - because the branch was squashed, rebased, or
merged in a way git cannot compare - GitHub or Azure DevOps is asked whether a pull request carrying exactly
those commits was merged into the default branch. A host can only turn "held" into "free"; it can never make a
copy that git already proved landed go back to held.

If any of that cannot be proven, the copy is **held**: it is left exactly as it is, nothing in it is reset or
deleted, and the reason is printed. You get it back with `cc-worktrees release --confirm-abandon`, which first
pins every commit it could not prove, in a place `git gc` cannot reach, then removes the directory. Work is
never thrown away quietly.

- Turn it on for a repository with `cc-devthrottle worktree pool on --repo <path>`. It is **off by default**,
  and there is no machine-wide switch: a repository opts in, one at a time. The default pool is four copies;
  `--size` sets your own. `worktree pool status` says where a repository stands, `worktree pool off` turns it
  back off. The setting is read each time a session is opened, so it applies to the next session and never
  moves one already running.
- The Director does the taking and giving back for you. Open a session in a repository that has the setting on
  and it runs in a pooled copy; close it and the copy goes back to the pool. If it cannot be proven, the first
  close does not remove the session: the row stays, carrying the tool's own reason, so you can see what is
  being kept. Closing a second time removes the row anyway, and the copy stays held either way - nothing is
  forced, retried with a stronger flag, or destroyed.
- The slot a session holds now survives a Director restart, so restarting no longer strands copies under
  holders that do not exist.
- A restart never helps itself to a copy somebody else holds. Taking a held copy is always somebody deciding to
  give up what is in it.
- The tool is `cc-worktrees`, and it ships in the toolbelt, on your path, on Windows, macOS and Linux. Every
  command takes `--json`, none of them prompts, and the Director's own commands are the same pool:
  `cc-devthrottle worktree get / return / list --pool / lease / destroy`.

Pooled worktrees have been tested end to end on Windows. The tool installs on macOS and Linux and has not
been tested there yet.

### One thing to know before you turn it on

**A `git gc` holds every copy in that repository's pool, including the free ones.** Part of the proof is git's
own record of what happened in a copy, and `git gc` - or `git reflog expire`, or the housekeeping git decides
to run by itself - rewrites that record. The tool cannot tell an ordinary tidy-up from somebody deleting the
evidence, so it refuses to call the work proven and holds the copy. Measured: a pool of four free copies
answered "pool full" to the next request after one ordinary `git gc`.

Nothing is lost, and the work in a copy held this way has almost always landed already. Getting them back is
`cc-worktrees release <slot> --confirm-abandon`, one at a time, which usually pins nothing and gives the name
straight back. We are shipping it this way on purpose: the alternative is a check that trusts a rewritten
record, and that is how unlanded work disappears.

## The Wingman tab: one screen to read a stop and answer it

The Now view on a session's Wingman tab is where you read what the Wingman made of a stop and answer it. It has
had a full usability round:

- **It says which session it is** - the number and the name, on the first line of every state. It did not,
  on the one screen you move between a dozen sessions on.
- **One place to type.** There was a box inside the card and a second box below it, with the loud blue button
  on the one that was not beside the question. There is now one composer, inside the card, and one sending
  button per state: Send for a stopped session, "Queue it" for a working one.
- **Stop, Interrupt, Compact and Clear context are off this screen.** They had arrived directly under where you
  click answers. Every other tab keeps them exactly as they were.
- **"Stopped at" is the real stopping time.** It read a join key as a time, which is why three sessions on two
  machines all claimed the same minute and one of them sat beside a row saying it had been idle for seventeen
  hours. It now comes from the Director's own record of when that terminal went quiet.
- **A finished session has somewhere to type**, with its own words: "Give it something else to do."
- **A snoozed session** says when it comes back and what it was snoozed over, and its first button wakes it.
- The pill wears the session's own colour, so the Wingman tab and the session list no longer disagree about
  what a session is doing. Options are numbered from one. An answer that cannot be taken back says so and asks
  once. A long ask is folded to three lines with "Show all of it" beneath, with the words untouched.

## Room for the report

A report was the narrowest thing on the screen it is the whole point of - a rail, a session list, a queue dock
and a conversation left it about 700 pixels of a 1920 display.

- **The left rail collapses** to an icon strip, and **the queue dock collapses** to a thin strip that keeps the
  control bringing it back and the number waiting. Both are remembered per browser. Collapsing is never a way
  to stop being told something needs you: the attention badge stays visible and every label stays in the page
  for a screen reader.
- **A report has its own address.** `/report/{id}` is the report itself, with nothing beside it. It used to
  forward into the Reports tab of the session that wrote it, which is the wrong screen for somebody who was
  sent the link and does not have that session. An open report carries a Full screen link to that address.
- **Export HTML** saves exactly the bytes the Gateway serves for the version on screen - a report is one
  self-contained file. It is in the report's own bar, so the Reports tab, the full screen page and the phone
  all have it.

## Voice: whose session it is, and the clip belongs to the turn you are looking at

- Voice mode narrates the sessions you own and not the ones another session holds - which is correct, and
  which nothing on the screen said. A held session now says so and offers nothing, and the banner claims only
  what the product does.
- **You can ask for a narration again.** A narration that failed can be retried by asking; automatic paths
  still never re-attempt one on their own.
- **The clip you can play is this turn's.** The rule that drops an old clip used to fire on an edge the
  Gateway samples, so a quick turn could slip past it: the session worked unobserved, went back to waiting, and
  the phone played the previous turn's audio as though it were this one, with both ends agreeing and both
  wrong. It now fires on a state check, so a missed transition costs nothing. Listening to this turn's audio is
  never cut off.
- A failed switch or generate stays on the screen until it is retried, instead of being wiped by the next poll
  three seconds later.

## Also in this release
- `cc-worktrees --version` answers like every other tool in the toolbelt, so its row on the Tools page is not
  red. The version is written down in exactly one place.
- The pooled-worktree commands print the proof they used in plain output, not only under `--json`.
- The mission workflow document has been reconciled with the DevThrottle Method, so the two no longer describe
  the same way of working in different words.
