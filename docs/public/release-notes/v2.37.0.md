## v2.37.0 - November 7, 2026

No machine should stop on a full Claude account while another account has room, and if one is heading that way you now hear about it every hour until it is fixed, not once.

### Highlights
- A warning that keeps going until it is fixed: when a machine is on an account at 80% of a limit, or the forecast says that account reaches 97% within 12 hours, and the machine holds no sign-in it could switch to, you get a phone notification every hour, an email whose subject names the machine and the hours left, and a bar across the top of every Cockpit, Director and phone screen. At night the phone stays quiet until the account is past 90%. The bar is yellow, and turns red only at 97%. It stops the moment the machine can switch. This replaces the single email and single notification the warning used to send.
- The Director shows the license bar too: until now the license warning appeared only in the Cockpit and on the phone.
- A coverage grid on the Licenses page: one row per machine, one column per paid account, saying whether that machine holds a fresh sign-in for that account. A missing sign-in is yellow at any usage level, and also appears as one quiet line in the daily report.
- A daily license fire drill: once a day the Gateway checks that every machine holds a fresh sign-in for every paid account, and runs one real switch out and back on a machine you choose. The result is a line in the daily report, and a failure raises the hourly warning. The drill does nothing until you choose its machine.
- A machine never loses a sign-in it holds: signing in to a new account by hand could leave the account the machine had been on held nowhere. That is fixed, and anything that would drop or overwrite a held sign-in now refuses and says so, or keeps the old one as a spare.
- Sign-ins renew a week ahead: every held sign-in is renewed seven days before it ends, not five, and a renewal that fails raises a warning and is tried again every day.
- Signing a browser in again from the mailbox: when claude.ai asks a browser profile to sign in again before it can approve a sign-in, `cc-devthrottle license reauth` requests the code, reads it from the account's own mailbox and types it in. It checks the page names the right account before it presses anything. Tell it which mailbox reads each account with `license set-mailbox`.
- The approver check survives a page that is still loading and a connection that drops for a few seconds, checks only the browser profiles you recorded for an account, and keeps the real reason when it fails.
- See how hard each machine is working: a memory and processor meter in the Director's toolbar and a banner when a machine is short. Each Director records the last 24 hours locally and sends five-minute summaries to the Gateway, the Fleet and Machines pages show each machine's capacity, and `cc-devthrottle machine diagnose` says what made a machine slow at a given time. Windows, Linux and macOS each have their own measurements.
- Your inbox for factories: a factory's messages now reach a Your inbox screen on the phone and in the Cockpit, with an unread count on the Inbox entry and a list, thread and reply box for each factory. The 08:00 factory email is replaced by one Your inbox message per factory with news, and no factory email is sent.

### Also in this release
- The Mission button in the Director, and the skills teach agents to start a mission with its document.
- A held spoken message to a factory is never dropped by the 24-hour clean-up, and its thread shows it is held.
- A factory seat's first prompt names the full path of its brief, a scheduled factory run switches installed plugins off, and every seat start names its model.
- A run that a check started owes its report, and a run waiting on a person without reporting reaches you.
- Hosted accounts can be given a 7-day Pro trial at their first Director. It is off by default.
- Every job in every build workflow now has a time limit.
- Several fixes to how the resource figures are measured and rounded, and to the tests that prove them.
