## v2.36.1 - November 6, 2026

On a Mac, the permission dialogs stop coming back. Until now every automatic update made macOS treat the Director as a brand new application and ask again for the permissions you had already granted.

If you are coming from v2.35.1, everything below is new to you. v2.36.0 was tagged earlier today but never published: the Mac build machine it asked for was retired that morning, so the release had no Mac files in it and was refused before anything reached the download page. v2.36.1 is that same release with the build machine corrected.

### Highlights
- Mac permission dialogs are granted once, not after every update: macOS records a permission against the exact identity of the application that asked for it. Every DevThrottle build used to have a different identity, so each automatic update threw away every permission you had granted and asked for all of them again. Every Mac build is now signed with one unchanging identity, so a permission you grant stays granted across updates. **Expect one last round of dialogs when you install this release** - the permissions you have today are recorded against the old per-build identities and cannot be carried over. After that they should stop.
- The launcher and the setup command line are signed on the Mac too: neither had ever been signed at all.
- A Mac Director started from the desktop can find your tools again: when the Director was started from its icon, the Dock or at login rather than from a terminal, it was given a bare search path with no `/usr/local/bin`, `/opt/homebrew/bin` or `~/.local/bin` in it. Every session it started inherited that, so a session could not run the agent, git, or Node. The Director now puts those directories back when it sees it was started that way, and leaves the search path alone when you start it from a terminal.
- Sessions no longer start in the root of the disk: a Director started from the desktop was given the root of the file system as its working folder, and handed that to every session it started. It now starts them in its own folder instead.
- Close can be offered at all: when a session finishes a turn, DevThrottle now inspects the repository that session works in. The report Close needs has to be newer than the session's own last activity, and before this the only reports came every six hours, so Close was refused for almost every session that had done any work.

### Also in this release
- The Factory can take work by inbox: a factory can be given work through its own inbox from the command line, one Secretary gathers each batch, and the Boss is woken for it. A factory inbox that stops moving raises an alert.
- Missions are first class: a Mission now carries a link to its document, and the Mission button reports its verdict on the Gateway.
- A factory definition with a blank brief is refused in the check's own words, naming the file, the line and the rule it broke, instead of failing later for an unclear reason.
- A Boss in a session that no factory started can publish its factory's definition.
- Two speed fixes: the idle rescan of every repository runs once an hour instead of every five minutes, and a repository's branch upstreams are read once rather than three times per branch.
- Your draft is never cleared when a machine short of memory cannot rule out an older sent message.
- A factory seat's kit folder is deleted when the seat stops, even when git is slow to let go of it.
- A stuck-inbox alert costs one database statement per poll rather than one per factory.
- A microphone quality test measures its samples from a fixed time rather than the machine's clock, so its result does not depend on when it ran.
- The Mac setup decisions agree on every machine, because they read Mac paths by Mac rules.
- Built with the .NET software development kit 10.0.403, for the patched ahead-of-time compiler.
- The Mac builds are made on a current build machine, after the one they had used was retired.
