Factory Inbox and Your Inbox

Mission document, version 3, final. All your answers recorded, 4 November 2026. Handed to the Delivery Lead.

What changed from version 1: the mission is now TWO inboxes, and the Boss never handles a message itself.

The factory inbox. You leave a message in a factory, typed or spoken, from the phone or the Cockpit. The Gateway starts that factory's Secretary, a short-lived seat that every factory gets for free. The Secretary reads the inbox, merges duplicates, files Good and Bad notes, marks each message "received", and hands one bundle to the Boss. The Boss judges the bundle and only delegates: it starts a session to do the work now, adds a to-do item for later, or declines and tells you why. It never does the work itself. Every message is logged with what was decided, so nothing is lost and you can see that it was listened to. Messages that were simply dealt with stay in the factory's record and do not message you. A factory summary can show them in the morning when you ask for it.

Your inbox. This is a mailbox inside DevThrottle for messages TO you, on the phone and in the Cockpit, which you read in the morning. It replaces the email that factories and sessions send you now. A Boss uses it only when something cannot be done, should not be done, or when it is pushing back on you.

What wakes the Boss: an event, with no polling. The message is written on the Gateway, so the Gateway knows the instant it arrives and acts on it directly. The tools for that already exist and are working today. Details in section 5.

5. Design

The path of one message

You: type or speak, Send -> Gateway logs it: Sent -> 60 s later: Secretary started, or rung if already running -> Secretary files it: Received -> Hands bundle to Boss: With the Boss -> Boss decides: Delegated / To do / Noted / Declined / Cannot be done

Only Declined and Cannot be done, plus a push-back, also write a message into Your inbox. Everything else is quiet, and you can see it on the factory's thread and in the factory summary.

What wakes whom, technically

No seat polls. The Gateway writes every message, so the write itself is the event. Each step below uses machinery that already exists and works today:

The Secretary

  • A seat the product gives every factory that has a Boss. Nobody defines it, and it runs on the Boss's computer in the factory.
  • Its job is to read new messages, merge duplicates, attach what each one is about (the run, report or record), and mark each one Received. A Good or Bad note is written into the factory's memory as a judgement for the Boss. It then hands ONE bundle to the Boss.
  • It never decides whether something is good or should be done. That is the Boss's job. It never starts work sessions. The Gateway enforces this: a Secretary's session key cannot start seats.
  • It closes itself when the inbox is empty and its bundle is handed over. If more arrives while it is still working, it is rung and stays open.

The Boss with a bundle

  • It reads the bundle with cc-devthrottle factory inbox bundle and decides each item with one command: decide <id> delegated --session <started session>, todo, noted, declined --why "...", or cannot --why "...". The last two, and pushback --why "...", also write to Your inbox.
  • "Delegated" is accepted only together with the id of a session the Boss actually started. "To do" adds a row to the factory's to-do list, which is a factory record, so it survives. That is how "never does it itself" becomes something the product can check, not just words.
  • It already may start any seat of its factory (Boss delegation, shipped). The new rule in its opening says it must not do the work itself.

Your inbox

  • Messages to you from a factory's Boss, from the factory's morning summary (instead of the email), and from any session (cc-devthrottle inbox send --subject "..." --body "..."). Each shows who sent it and links to the session, report or factory it came from.
  • Unread, Read and Archived, like email. The count shows on the Inbox entry. Nothing in it is an alert. Alerts stay for things that need an answer now, and dev reports stay for documents with questions.
  • It is kept like a mailbox, and nothing is deleted by the system.

Voice

Voice uses the same durable voice box and upload the phone and Cockpit already have, with its target set to a factory inbox instead of a session. It is transcribed under the verbatim rule: the stored message is the speech model's text plus only your hand-listed corrections, and the raw text is kept beside it.

The factory summary

The summary is built by the Gateway from the log, so no agent needs to start. It shows what came in since a time, and the decision on each item, as counts and lines. The thread's Summary button shows it, and each factory's morning message in Your inbox carries it.

Out of scope

  • Sending email to other people. That stays as it is.
  • Changing fleet messaging between sessions.
  • Messages to seats other than the Boss. The Secretary only ever hands to the Boss.

7. The check

Every task: .\scripts\test-local.ps1 green, plus -Parked because the Gateway changes; the client-core and phone web tests; and a separate review.

Gateway tests that must exist and pass:

  • Three messages in one second start exactly one Secretary.
  • A running Secretary is rung and no second one starts.
  • A ring is never typed while the session works or holds your draft.
  • A Boss session that is alive is rung, never doubled.
  • "Delegated" without a started session is refused.
  • A Secretary's key cannot start a seat.
  • A claim held by an ended session is taken by the next one.
  • A message not received in 15 minutes raises the stuck alert.
  • A spoken message equals the raw transcript plus only listed corrections.
  • Declined, Cannot be done and push-back each write exactly one Your-inbox message. Delegated, To do and Noted write none.

End to end on the deployed Gateway, with a test factory on a test Director in slot 5, driven through the phone and Cockpit screens with browser-harness. Screenshots and the session list are taken at every step:

  • A spoken Bad note is sent from the phone. One Secretary starts, marks it Received, hands it over, and closes. One Boss starts, delegates to a Writer session, and the thread shows the full trail.
  • A second message is sent while the Boss is still alive: no second Boss, and the decision arrives.
  • A request the Boss should refuse becomes "Declined" on the thread and one new message in Your inbox. A reply from Your inbox lands back in the factory inbox.
  • A session sends a message with cc-devthrottle inbox send. It appears on the phone and in the Cockpit, and no email is sent.
  • Failure cases: the Director is stopped (the thread says why, and work resumes on reconnect), the Secretary is killed mid-claim (the next one takes it), the stuck alert is raised, and an archived factory is refused in words.
